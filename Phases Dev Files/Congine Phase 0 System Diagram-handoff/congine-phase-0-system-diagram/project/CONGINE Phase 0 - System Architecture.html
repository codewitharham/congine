High-Level Design

A stateless, deterministic local-plane validation kernel. Five concentric layers; dependencies point strictly inward; zero network on the hot-path once bootstrapped.

Architectural Philosophy · Direction of Dependencies

Outer layers depend only on inner abstractions. No inner layer holds any reference to a concrete outer wrapper — the arrow of dependency points one way: inward ▸.

Non-Functional Requirements · Architectural Guarantees
NFR-01 Latency

Sub-200ms p99

The guard hot-path performs zero network calls. Schemas resolve from an in-process O(1) LFU cache; a ValidationTimer caps each run at timeout_ms and degrades rather than stalls.

NFR-02 Isolation

Memory bounding & tenancy

Cache capacity and TTL are hard-bounded. Tenant identity rides every request header; containers are instantiable per-tenant with no shared global state.

NFR-03 Autonomy

Zero-dependency execution

Once bootstrapped from snapshot, the hot-path needs no control-plane, DB, or telemetry server. Telemetry is fire-and-forget; failure degrades silently.

Boundary Conditions · Phase 0 Scope
▣ Inside the boundary
  • Local, in-process payload validation (6 rule taxons)
  • In-memory O(1) LFU schema cache with TTL
  • Synchronous & asynchronous entry execution
  • Atomic on-disk snapshot for offline bootstrap
  • Fire-and-forget telemetry buffering
  • Constructor-wired composition root
▢ Outside the boundary
  • Control-plane database & contract authoring
  • Telemetry ingestion / storage servers
  • Schema versioning & promotion workflows
  • Auth issuance & key rotation
  • Cross-process / distributed cache coherence
  • Dashboards, alerting, SLO evaluation

03

Workflow A · Bootstrapping & Sync Lifecycle

Cold start: environment → container assembly → cache priming from snapshot → daemon provisioning. Runs once, off the hot-path.

04

Workflow B · Hot-Path Guard Interception

Steady state: @congine_guard intercepts a call, resolves the schema from cache, runs local rules under a timeout, and fires telemetry — all without leaving the process.

05

O(1) LFU Cache · Internal Structure

Ketan-Shah three-structure design: key→value, key→freq, and freq→OrderedDict acting as a per-frequency LRU chain. Constant-time get, put, and eviction.
